## 一、目标与优先级（和用户讨论后定的）

**搜索第一。** 入影库 = 把分享的目录树抄下来建本地索引；首页搜索、⌘K、影库页、MCP 都能搜；资源对不对由人在结果里看（目录名、画质、路径、文件名），或智能体 `share_inspect` 后判断。
**TMDB 匹配放第二阶段**（入库后后台识别、别名进索引、海报墙、版本合并），它只让搜索更准更好看，不决定搜不搜得到。

用户拍板（2026-09-28，「都按照你的推荐」）：

## 二、数据模型（迁移 0017）

### `media_library`（「来源」：收藏的一个分享或其中一个目录）加列

`share_title`、`index_status`（pending / indexing / done / failed）、`index_error`、`index_gen`（当前第几轮抄）、`indexed_at`、`index_started_at`、`index_retry_at`、`dirs_total`、`dirs_listed`、`node_count`、`video_count`、`total_size`、`truncated`。存量条目升级后是 pending，后台补抄。

同一分享的来源不重叠：已收整包再收子目录 → 409「已在『老K』里」；先收了子目录再收它的上级 / 整包 → 新来源吸收旧的（删旧来源和它的索引，标签备注并过来）。替换原来按 `(share_code, share_path)` 的唯一约束判重。

### `library_nodes`（索引）

一行一个目录或文件：`source_id`（外键，级联删）、`node_id`（分享里的 id）、`parent_id`、`name`、`path`（分享内完整路径，不带前导 /）、`is_dir`、`depth`（来源根是 0）、`size`（文件字节；目录抄完回填子树合计）、`token`（夸克转存要的）、`gen`（哪一轮抄到的）、`listed_gen`（目录：哪一轮列过下一层）、`video_count`（目录：直接放着的视频数）、`missing`（分享还在但这个目录打不开了）、`search_text`（目录：归一化的 `路径|名字|直接文件名`；文件留空）。主键 `(source_id, node_id)`，索引 `(source_id, parent_id)`、`(source_id, is_dir, listed_gen)`。

整个分享的来源，根用 `node_id = "0"`、名字是分享标题。

### `library_shares`（分享死活，按分享码）

`share_code`（主键）、`kind`、`status`（unknown / ok / suspect / expired / locked）、`reason`、`fail_streak`、`checked_at`、`last_ok_at`、`expired_at`、`next_check_at`。有来源时建，最后一个来源删掉时删。

## 三、抄目录（索引）

`services/library/indexer.ts`，单个后台工人，一次抄一个来源；**轮流**：每趟最多列 40 个目录，有别的来源在等就让出来（挑最久没轮到的），大包抄着时后加的小分享不用排到大包抄完。加入时先查一次分享（提取码不对、已失效当场记下，不去排队）。

- **宽度优先**：每次取「本轮还没列过」的目录里最浅的一个，列完（全部翻页）→ 子节点入库 → 本目录的 `search_text` 补上直接文件名、`video_count`、`listed_gen = gen`。插入时目录的 `search_text` 就先有「路径 + 名字」，所以浅层一列完就能按名字搜。
- **让路**：115 走单独一条单并发通道；发请求前看账号级限流器有没有别人在排队，有就等（最多几秒，防饿死）；两次抄之间留一点间隔。夸克同理。
- **可续**：进度全在库里（`listed_gen < gen` 的目录就是待抄），重启后接着抄；进度 `dirs_listed / dirs_total` 每批、让路、停下（暂停 / 失败）时都按库里的实际数写回来源。
- **刷新**：`gen + 1` 重抄，旧节点照常可搜，抄完删掉 `gen` 小于本轮的（内容删了的就没了）。
- **出错**：`ShareGoneError` → 交给分享死活处理（见四），来源停下（失效 / 提取码不对记 failed，疑似失效等复查后接着抄）；网络 / 超时 / 风控 → 同一目录退避重试三次，再不行整个来源暂停一段时间（`index_retry_at`）再续；账号失效 → 暂停一小时，错误写明。
- **上限**：一个来源最多 5 万个目录 / 20 万个节点，超了停下标 `truncated`。
- **收尾**：子树大小回填、统计写回、`index_status = done`、`indexed_at`。
- 来源被删时工人在两次列目录之间发现就停。

老的刮削工人（TMDB 海报）第一阶段只给「看起来是一部作品」的来源用（抄完后视频目录 ≤ 1 个），整包不刮，免得「老K」配上错海报。第二阶段替换掉它。

## 四、分享死活（失效处理）

`services/library/health.ts`。

- **钩子**：`drive/registry` 给分享 Provider 套一层观察者（`setShareObserver`），所有用到分享的地方（弹框、转存、智能体、Telegram、追更、抄目录、巡检）成功 / 失败都顺带报上来，不用每个入口各写。只记影库里有的分享码。
- **只有根上的失败算分享级**：`open` / `info` / 列根目录失败才计；列子目录失败先查一次根，根好的就是那个目录没了 → 该节点标 `missing`、重抄它的上一级；根也坏才按分享失败计（115 把大部分分享接口报错都当成「分享没了」，子目录不存在也可能这样报，不能一次就判整包死）。
- **判定**：提取码问题 → locked；根上明确说取消 / 过期 → expired；其余 → suspect，`fail_streak + 1`，`next_check_at` 按 30 分钟、3 小时退避复查，连续 3 次 → expired；任何一次成功 → ok、清零。
- **巡检**：每 10 分钟一轮：到点的 suspect 复查；超过 24 小时没查过的（不含 expired）逐个查 `info`（每个分享一次请求，礼让）。设置里能关（默认开）。
- **搜索时查**：结果里涉及的分享超过 6 小时没查过，前端拿到结果后调检查接口（一次最多 10 个），回来再更新标记；MCP 在一个小预算里（几秒）查排在前面的。
- **确认失效之后**：搜索里折叠到「已失效 N 条」，每条有「找替代」（先在影库其他分享里找同名有效的，再去 PanSou，关键词从名字提）；来源卡片上「找替代 / 更新链接 / 移除」；「更新链接」验证新链接能打开后换掉分享信息、重新抄（标签备注保留，内容差很多时提醒）；locked 的可以改提取码（同一分享的所有来源一起改）。
- **清理**：影库页筛选「已失效 N」里右上角「清理全部失效的分享」→ 确认框写明只删影库记录和索引、网盘和 strm 不动；疑似失效的不在批量清理范围。
- **再查一次**：巡检不再查已失效的（别老去碰死链），但 115 分享审核中这类含糊失败三连也会判失效、审核完又能打开——失效 / 提取码不对的来源菜单里「重新建索引」换成「再查一次」：`POST /refresh` 先真去问一次网盘，还是打不开回 `SHARE_GONE` + 原因，没问到网盘（查的时间没变：网络、账号问题不记在分享上）回「这次没查成」。
- **恢复后接着抄**：分享从失效 / 提取码不对变回能打开（谁用到时发现的都算：再查一次、弹框、转存、智能体、改提取码），因为分享停下的来源（`indexError` 以「分享已失效」「提取码不对」开头）接着那一轮抄（一个目录没抄过的从头来）；已经抄完的索引是好的，不重抄。
- **通知**：巡检确认失效时推 Telegram「影库里的分享『老K』失效了（N 个目录）」，开关 `notify.library` 默认开；正在用时发现的只在网页 / 工具结果里说。

## 五、搜索

- **归一化**（`services/library/search-text.ts`）：去不可见字符、转小写、全角转半角、罗马数字转阿拉伯数字（Ⅱ→2）、去掉空白和标点（点号、下划线、括号、冒号……）。目录的 `search_text` = 各段归一化后用 `|` 连起来：`路径各段 | 名字 | 直接文件名`。
- **查询**：按空白和括号拆词（「末日地堡(2023)」是两个词；点、冒号不拆，「A.I.」拆成单个字母什么都对得上）、逐个归一化，全部 `LIKE '%词%'`（AND）。SQLite FTS5 默认分词不切中文、trigram 要 3 个字以上，所以不用它；影库量级（一个大包一两万节点）LIKE 几毫秒。
- **年份只加分**：还有别的词时，年份（19xx / 20xx）不参与筛选，对上了 +15 分——目录名、剧集文件名里常常不写年份（「老K/2. 剧集/末日地堡」），搜「末日地堡 2023」不能搜不到；只有年份的（「2046」「1917」本身是片名）照常要对上。
- **排序**：名字里就有全部词 > 靠文件名命中 > 只靠路径命中；名字等于 / 开头于 > 包含；直接放视频的目录加分；浅的优先。
- **收拢**：同一来源里，祖先目录自己命中了，命中的子孙收进它（「神探夏洛克」下四个季目录都命中 → 一条，带「4 个子目录也命中」）。
- **找替代的关键词**（`keywordOf`）：到第一个像发布信息、年份、季集的词为止；括号、点、下划线当分隔，【】[]{} 标签整个去掉，圆括号当片名结尾；**不带年份**——和 `pansou/normalize.ts` 的 `keywordFromName` 同一个口径（年份塞进关键词只会让网上搜得更少）。搜索页上关键词就是当前搜索词时不给「找替代」按钮（替代的就列在同一页，点了原地不动）。
- **结果**：目录名、分享标题 + 路径、面包屑（带 id，打开弹框直接定位）、大小、直接视频数、前 3 个视频文件名、画质标签（沿用资源搜索的 `titleTags`）、分享死活、索引时间；失效的单独给个数（要才给明细）；有来源还在抄时附一句「还在建索引，结果可能不全」。

## 六、接口

- `GET /api/library`：来源列表带上索引进度、统计、分享死活。
- `POST /api/library`：加入（判重叠 / 吸收）→ 排进索引队列。整包不再按分享标题刮削。
- `POST /api/library/:id/refresh`、`POST /api/library/:id/relink {shareUrl}`、`PUT /api/library/:id`（改提取码对同一分享的来源一起生效，改完查一次）、`DELETE /api/library/:id`、`DELETE /api/library/expired`。
- `GET /api/library/search?q=&limit=&offset=&expired=1`。
- `POST /api/library/shares/check {codes}`。
- 115 的 `ShareInfo.fileCount` 其实是总字节数：改成 `size`，影库统计一律用索引算的。

## 七、前端

- **影库页**：顶上搜索框（`?q=` 同步到地址）；有词时是结果列表；没词时是来源卡片（有封面用封面，否则分享图标 + 标题）+ 状态行（索引中 45% / 已索引 12,340 条 · 3 天前 / 疑似失效 / 已失效 / 提取码不对）+ 菜单（打开、刷新索引、更新链接、改提取码、编辑、移除）；筛选「全部 / 索引中 / 已失效 N / 提取码不对 N」；「添加分享」按钮（贴链接直接整包入库，大包不用先开弹框）；有来源在抄时轮询。
- **结果列表组件**（影库页和首页搜索共用）：一行一个目录，操作「打开（弹框定位到这一层）/ 转存到任务 / 复制链接」；失效的折叠在最后，带「找替代」「去影库清理」。
- **首页搜索（/search）**：影库一块置顶，没配 PanSou 也能搜（原来整页不可用，改成只提示「网上资源要先配 PanSou」）；显示后对结果里的分享做死活检查。
- **⌘K**：打两个字以上就防抖去搜影库，前 5 条成一组，回车直接打开分享弹框定位到那个目录；另有「在影库里搜『…』」跳影库页。
- **分享弹框**：加入影库后提示「已加入，正在建索引」；判重叠的 409 说清楚；只勾了文件时不再退化成收当前目录（提示按目录收）。
- **设置页**：新增「影库」一节（每天检查分享是否失效，默认开）；Telegram 页通知开关加「影库分享失效」。

## 八、MCP

- **`library_search`**（只读，transfer 组）：`keyword`、`limit`、`includeExpired`；结果每条带 `link`（含提取码）、`dirId`（上一级，给 share_save）、`itemId`（这个目录，给 share_inspect 当 dirId、给 share_save 当 itemIds）、路径、大小、画质、文件名样本、分享死活；失效的只报个数；排在前面的分享顺手查死活（几秒预算）。
- **`resource_search`**：结果多一个 `library`（前几条，同上形状）；没配 PanSou 不再报错，只返回影库结果并说明。
- **说明 / prompt**：找资源先 `library_search`（瞬间），没有或不合适再 `resource_search`；影库条目用 `share_inspect(link, dirId=itemId)` 看内容再判断对不对。
- `share_inspect` / `share_save` 碰到影库里的分享打不开：提示里加「影库已记下，先换影库里别的来源（library_search），再去网上找」。
- 工具快照更新（只加不改）。

## 十二、第二阶段方案（2026-09-29 开工）

目标：抄下来的目录树里认出一部部作品（TMDB），影库能按作品看（海报墙、同一部的几个版本合成一张卡），搜索能用正式名 / 原名 / 英文名 / 别名找到（「silo」→ 末日地堡），认错了能换。第一阶段的搜索、转存照旧，识别是在上面加一层。

**A. 片名解析认中文分享包（parse-name，整理也受益）**
- 技术词判断加一条：含汉字的词里粘着发布信息就切断标题——原盘 / REMUX / 蓝光 / 杜比视界 / 国英双音 / 内封字幕 / 高码率 / 豆瓣8.8 / 奥斯卡提名 / 单集9G / 共87.59G / 760G / 全5季 / 全4部 / 两部4K… / 收藏版。只看含汉字的词，英文发布名照旧走原来的词表。
- 年份后面跟着汉字词（「七宗罪 1995 布拉德皮特」）：标题到年份为止。
- 标题带罗马数字（冰雪奇缘Ⅱ）多给一个阿拉伯数字的候选。
- 大包里的真名字进 parse-name.test.ts 的样本表；整理的测试全过。

**B. 作品单元（从索引切，不请求网盘）**
- 来源抄完后，拿索引里的文件跑整理的 `buildUnits`（识别词、视频扩展名同整理；库类型 mixed）：季目录、花絮归上一级，合集里一部一个单元，散在分类目录里的文件按标题拆。
- 新表 `library_units`（迁移 0018）：来源、单元键（根目录节点 id；拆开的加标题）、根节点、路径、原名、解析出的标题 / 年份、类型猜测、季号列表、视频数、大小、代表文件、是否自己的目录、视频文件节点 id（散文件转存用）；识别结果：状态（pending / done / manual / ignored）、tmdbId、类型、标题、原名、英文名、年份、海报、把握、理由、备选、识别时间、下次重试。
- 重建单元时按单元键保留已有的识别结果（名字变了才重认）；手动的永远保留。
- 升级上来（rc.1 已经抄完的来源）和切单元的规则改了：启动时补切（`library.unitsVersion`）。

## 识别调整与「一起转存」（2026-09-29 下午，实验库 lab3 + 老K 全量回归）

## 批量添加（2026-09-29 晚）

用户问「添加分享的时候可以一次添加多个吗」：原来不行，而且框里贴了好几个只会加第一个、后面的悄悄丢掉。用户说「加上批量添加」。

- 认链接放在后端（`registry.ts` 的 `findShareLinks`，和加的时候同一套认法）：按出现的先后，提取码只有一个链接时整段里找（和原来一样，写在前面也认），好几个时各找各的（链接后面、下一个链接前面那段）；同一个分享只留一条（前面没码、后面有就用后面的）；一个网址都没有时整段一个裸分享码认，一行一个的不认——随便一个英文词（Movie、4K、123456）都能当成 115 的码。
- `POST /api/library/links { text }` 给预览：每个分享的类型、码、带码的链接、有没有提取码、是不是已经整包收着（和加的时候判重叠同一个 `coveringOf`），收着的带上它在影库里的名字。
- 加还是一个一个走原来的 `POST /api/library`：每个都要去网盘问一下分享，一个接口里串几十个会被反代 / Cloudflare 的 100 秒掐断，前端逐个发还能显示进度。
- 界面（影库页 `AddShareDialog`）：边贴边认（停手 300 毫秒），列出「认出 N 个分享，其中 M 个已经在影库里」；一个的和原来一样（加上就关、toast，分享打不开的改成黄色提示）；好几个的按钮是「加入 N 个」，逐个加、「正在加第 i / N 个」，每行一个结果：加上了（分享标题）/ 加进来了但分享打不开（失效、提取码不对）/ 已经在影库里 / 失败（原因），加完 toast 汇总、框里留着结果、「完成」关掉。

真机（实验库，配置只读拷贝、Telegram / 网盘监控 / Emby / HDHive / TMDB 全关、老的影库条目删掉）：贴「老K（访问码在后面）+ 编的夸克链接（提取码在后面）+ 编的 115 链接 + 老K 带码的重复一行」→ 认出 3 个（重复的并掉）→ 加入 3 个：老K 加上（标题「老K」、开始抄）、两个编的「加进来了，但分享打不开：分享已失效」，toast「加入了 3 个，其中 2 个分享打不开」；再贴老K →「其中 1 个已经在影库里」、按钮灰掉；乱写的一段话 →「没认出分享链接」；390px 窄屏正常。测完把三条删了（老K 抄了十几个目录就停），实验库已删。
