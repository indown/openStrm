# 命令面板（⌘K）—— 方案

> 2026-09-17 起草，基于 `worktree-task-ui` 的 `74286a8`（= v2 的 `37feca8` + 表单那一轮五个提交）。**还没动任何代码。**
> 上一轮见 `ui-forms-layout.md`。那轮修控件语义，这轮修**入口深度**。

---

## 一、它解决什么

11 个页面，动作藏在弹框和下拉菜单里，侧栏还能折叠成图标条。现在"开始同步狂飙"是：点侧栏 →
等任务页加载 → 在表格里找到那一行 → 点 ▶。strm 管理、整理、云下载这些页表格一长还得先滚。

面板把"去哪儿 + 做什么 + 找什么"收成一个不用鼠标的入口。

---

## 二、一个修正：比先前说的便宜，**首版零后端改动**

先前跟用户说过"后端大概率要加一个统一搜索接口"。读完数据层撤回这句：

- 要搜的实体确实都在 SQLite 里（`db/schema.ts`），但**量都很小**：任务几十条、账号个位数、追更几十条。
- 前端已经有 `/api/task`、`/api/account`、`/api/follow` 三个现成的列表接口。**面板打开时并发拉一次、缓存在会话里、在内存里过滤**就够了 —— 不用防抖、不用取消旧请求、不用新接口、不用新迁移。
- 顺带一个发现：`tasks` 表把任务整体存成 JSON blob（`schema.ts:18`，只有 `account_name` 是列），所以就算写服务端搜索，`originPath` / `targetPath` 也 LIKE 不了，照样得全读出来在内存里过 —— 那还不如直接在前端过。
- 唯一真需要服务端搜的是影库（`media_library.title` 可能上千条），而**影库入口现在是关着的**（`lib/features.ts` 的 `libraryEntry: false`）。等真开了再加接口。

---

## 三、明确不进实时搜索的东西

| 东西 | 为什么不进 | 改成什么 |
|---|---|---|
| strm 文件 | `/api/strm/search`（`services/strm/manage.ts:300`）是**按任务走整棵文件树**，还带 `WALK_ENTRIES` 上限。每敲一个键跑一次不可能 | 一条命令「在 strm 里搜 "xxx"」→ 跳 `/strm?taskId=…` 并把词交给那一页 |
| 生活事件、执行历史、整理条目 | 量大、要分页 | 同上，面板只负责送到那一页 |

原则：**面板里能实时过滤的，必须是内存里就有的**。凡是要打网盘、走文件树、翻页的，面板只做交接。

## 四、搜什么 / 回车之后做什么

### 4.1 命令（前端硬编码，不需要任何请求）

- **导航**：`lib/nav.ts` 的 11 项，直接复用，`FEATURES` 关掉的不出现。
- **全局动作**：新建任务、粘贴分享链接、立即检查更新、下载备份、浅色 / 深色 / 跟随系统、修改密码、退出登录。

### 4.2 实体（打开面板时拉一次）

| 类型 | 匹配字段 | 回车 |
|---|---|---|
| 任务 | `originPath` / `targetPath` / `account` | 进它的动作段（见 4.3） |
| 账号 | `name` / `accountType` | `/account` |
| 追更 | `name` / `watchPath` | `/follow` |

### 4.3 两段式

打 `狂飙` → 回车 → **面板不关**，换成这个任务的动作列表：

> 开始同步 · 实时日志 · 执行历史 · strm 目录 · 整理这个任务 · 编辑

Esc 或在空输入框上按 Backspace 退回上一段。cmdk 官方的 "pages" 模式，一个栈 + 几行判断。

**深链基本都现成**（这个 app 本来就靠 query 传状态，且都按静态导出的要求包了 Suspense）：

- `/strm?taskId=<id>&path=<rel>`（`use-strm-browser.ts:56`）
- `/organize?task=<id>`（`organize/page.tsx:70`）
- `/history?taskId=<id>`、`/log?taskId=<id>[&executionId=]`（`log/page.tsx:93`）

**唯一缺的**：`/home` 的新建 / 编辑弹框是页面本地 state，没有 query 入口。加 `?new=1` 和 `?edit=<id>`，写法和上面这些一致。

## 五、依赖：引 cmdk

`cmdk@1.1.1`，**MIT**，解包 82KB（运行时 gz 约 5–6KB）。四个依赖 `@radix-ui/react-{id,dialog,primitive,compose-refs}` **node_modules 里已经全有**（dialog 是直接依赖，另外三个是 select / menubar 带进来的），所以实际只多一个包、不动依赖树。

自己写行不行：能，150–200 行，但要自己做筛选排序、roving focus、`aria-activedescendant`、选中项滚动跟随、组标题跟随过滤显隐。Switch 那种 30 行的控件值得自己写（见 `ui-forms-layout.md`），这个不值得 —— 何况 cmdk 就是 shadcn `Command` 的底座，接现有 token 零成本。**建议引。**

## 六、键盘与入口

- **⌘K / Ctrl+K** 全局。已有的 ⌘B（侧栏，`ui/sidebar.tsx:96`）和设置页的 ⌘S 都不冲突。
- **已经有弹框开着时不响应** —— 两层 Radix Dialog 的焦点陷阱会打架。判断条件：页面上存在 `[data-slot="dialog-content"]` 或 `[data-slot="alert-dialog-content"]`。
- **手机没有 ⌘K**：顶栏加一个搜索图标（和现在"分享链接"在手机上收成图标是一个做法）。桌面上给一个显示 `⌘K` 的按钮。
- **动态 import**，不进首屏共享包（照 `LayoutWrapper` 里 `ShareDetailDialog` / `HdhiveSearchDialog` 的写法）；常驻的只有那个 keydown 监听。

## 七、一个可选的简化（单独决定，不进首版）

顶栏那个 288px 的「粘贴 115 / 夸克分享链接」输入框，面板完全可以吃掉：往面板里粘 `https://115.com/s/...`
就识别成分享链接，回车直接开转存弹框。顶栏省出一大块，全站只剩一个输入入口。

不放进首版的理由：要动 `useShareDetail` 的挂载位置，而且改掉了用户已经用熟的操作。等面板本身站稳再说。

## 八、落地顺序（每步之间都能停）

| 步 | 内容 | 依赖 | 估时 |
|---|---|---|---|
| 1 | 装 cmdk + `ui/command.tsx`（shadcn 那份，接现有 token） | cmdk | 半小时 |
| 2 | `command-palette.tsx`：命令段（导航 + 全局动作）+ ⌘K + 顶栏入口 | 无 | 2 小时 |
| 3 | 实体段：打开时并发拉 task / account / follow，会话内缓存，内存过滤 | 无 | 1 小时 |
| 4 | 两段式动作段 + `/home?new=1&edit=<id>` 深链 | 无 | 2 小时 |
| 5 | 「在 strm 里搜 xxx」这类交接命令（strm 页读 `?q=`） | 无 | 1 小时 |

**第 2 步单独发出去就已经可用**（导航 + 全局动作），后面三步是加料。

## 九、验证

- 浅色 / 暗色 / 420px 窄屏三遍。
- **打开不能阻塞**：三个列表接口并发，没回来之前命令段就能用；拉失败只是少了实体段，不刷 toast。
- **键盘全程可达**：⌘K 开、↑↓ 选、回车执行、Esc 关、空输入框 Backspace 退段；关掉后焦点回到打开前那个元素。
- **首屏共享 JS 不能涨**（现在 100 kB）：面板必须切成独立 chunk。
- 已有弹框开着时按 ⌘K 不弹面板。

## 十、首版不做

- 影库搜索（要服务端，且入口关着）
- strm 文件实时搜索（第三节）
- 最近用过 / 使用频率排序（要存状态，先看有没有人真需要）
- 吃掉顶栏的分享链接框（第七节）
