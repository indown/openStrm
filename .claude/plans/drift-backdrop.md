# 海报背景（任务 / strm 管理 / 整理页）—— 方案与实施记录

一面 3D 倾斜的海报墙，压暗压糊铺在内容后面。灵感来自 reactbits 的 DriftWall，但只借机制，
代码是自己写的（reactbits 是 MIT + Commons Clause，抄源码进仓库要保留版权头，和「代码里不写第三方项目名」冲突）。

参照物不是落地页，是 **Emby / Jellyfin / Plex 的详情页背景**：一张作品图放大、模糊、压暗铺满。
对一个 strm 工具来说这是本行的语言，不是从营销页搬来的装饰。

## 一、定下来的形态

用户在「内容带 / 页头背景 / 整页背景」三个方案里选了**整页背景**，并要求做 3D（不是分层假纵深）。

两个状态，判定只有一条规则：

| 状态 | 判定 | 表现 |
|---|---|---|
| `stream` | 当前路径的祖先里**没有**带 id 标签的段 | 若干列海报缓慢上下漂移，列在 Z 轴上深浅不一 |
| `single` | 祖先里**有** `[tmdbid=…]` | 就这一张，倾斜、放大、糊掉，**完全静止** |

剧集和电影一视同仁，也不分层：`剧名 (2024) [tmdbid=1]`、它的 `Season 01`、`Season 01/extras`
进哪一层都是同一张。命名里不写 id 标签的库退一步：拿当前目录和它的父目录去碰运气。

## 二、海报从哪来：四级回退（`services/strm/poster.ts`）

| 级 | 来源 | 靠什么 | 要不要外网 |
|---|---|---|---|
| ① `local` | 目录里的 `poster/folder/cover/default.{jpg,jpeg,png,webp}` | 默认 `downloadExtensions` 就带 `.jpg/.png`，图片随片下载到本地了 | **不要** |
| ② `tmdb` | 目录名里的 id 标签 → TMDB 详情缓存 | `organize/identify.ts` 的 `idTagFromName()`，三种风格通吃 | 缓存命中就不要 |
| ③ `tmdb` | `tvshow.nfo` / `movie.nfo` 里的 tmdbid | `organize/nfo.ts` 的 `readNfoFacts()` | 同上 |
| ④ `run` | 这个任务最近 10 次整理记录里的 `organize_units.match`（自带 `posterUrl`） | `dstRoot` 和本地相对路径是同一串 | **不要** |

①③④ 全部离线可用——这个产品跑在 NAS 上，不少人没填 TMDB key，也有人不想让 NAS 连外网，
所以**海报能力不建立在「必须有 key」上**。②③ 缓存没命中且没 key 就静默跳过，不报错、不留空框。

**查的顺序是「离线的四级全试完，最后才联网」**（2026-09-18 起，见第八节）：① → ②③ 只查缓存 → ④ →
还缺的、手里有 tmdbId 的才去 TMDB 现查。原先是 ②③ 缓存没命中就当场联网、④ 排在联网之后，
整理过的作品明明记录里就有海报，也要先排队问一遍 TMDB。④ 只在和 id 线索说的是同一部时算数；
说的不是同一部，先拿它顶着，联网问到线索那部的图再换。

TMDB 详情缓存和 `organize/identify.ts` 的 `TmdbClient` **共用一份**（键都是 `details:<kind>:<id>:<lang>`）。

### 接口

```
POST /api/strm/posters  { taskId, paths: string[] }   # 一次最多 48 个目录
  → { posters: { [path]: { source, url, title?, year?, tmdbId? } } }   # 拿不到的不出现

GET  /api/strm/image?taskId=&path=                    # 本地图片，只放行图片扩展名
```

两个都复用 `manage.ts` 的 `resolveManagedPath()`（越界 + 符号链接检查现成的）。
`/image` 带 `Content-Type`、`ETag`（size+mtime）、`Cache-Control: private, max-age=86400`，
超过 16MB 不给。

**`<img>` 带不了 Authorization 头**，所以本地图片是前端 `fetch` 成 blob 再 `createObjectURL`
（现在在 `lib/poster-images.ts`，见第八节）。没有把 token 放进 URL——会落到日志和 referrer 里。

## 三、3D 几何（`components/poster-backdrop.tsx` + `globals.css` 的 `.poster-backdrop`）

```
perspective: 1200px（和参考实现同一档）   perspective-origin: 60% 42%
列的 translateZ: -300 ~ +40
平面: rotateX(16°) rotateY(-14°) translateZ(-120px)  ← 先转再沿自己的法线往后推
      尺寸按视口算（X 1.7 倍、Y 1.5 倍），封顶 3600×1800
瓦片: 190×285（2:3），间距 20，速度 12px/s 基准，列间黄金分割伪随机、方向交替
空气透视: 越远 → 越糊（blur 1.5~6px）、越淡（opacity .5~1）、越小（透视自带）
遮罩: radial-gradient(ellipse 105% 105% at 60% 8%)，铺满大半屏、四周渐隐，热点偏右上让开标题
不透明度: 暗色 .22 / 浅色 .14；单作品态 .38 / .16
```

**倾角 / 墙的尺寸（OVERSCAN·MAX）/ `PLANE_Z` 的后推 / 瓦片大小是一组，动一个就要重算其余三个。**
试过 -22°：只抬倾角的话，① 远端收缩过头，屏幕左上角露出墙外的底色；② 近端放大到 2.58×，
瓦片大得不像墙。把 OVERSCAN 加到 2.1 / 2、后推到 -280、瓦片缩到 150×225 能补回覆盖，
但一屏就变成一百来块——**太密，反而不好看**。最后定在 -14°：一屏三四十块、块够大看得出是海报，
四角也都盖住（六个探测点实测全覆盖）。视点从 50% 50% 挪到 60% 42% 是这一版唯一保留下来的补丁，
它把远端在屏幕上摊得更开，不增加列数就能盖住左上角那个最远的角。

**列是 `overflow: hidden` 的，于是 `transform-style` 被强制 flat**：每一列先拍平成一个 2D 面，
再整体摆进 3D。这是好事——单块瓦片不可能自己冲到相机跟前炸开，风险只剩"整列"这一个粒度，
而列的 Z 是我自己给的、有界的。（注意：这也意味着用 `getBoundingClientRect()` 量被裁掉的瓦片
会读到几十万像素的假值，别拿它当炸开的证据，要量就只量视口内的。）

**超宽屏靠 `PLANE_MAX_W` 封顶**：不封的话 4K 屏上斜着的墙左端会自己伸到相机跟前。

**踩过的坑（改几何前必看）**：透视里元素的 Z 一旦逼近相机距离（`perspective` 值），投影会炸开——
第一版用了 `scale(1.7)` 放大平面 + `perspective: 1400px` + 16°/18° 倾角，
实测有列被放大到 **49000px 宽**，整面墙只剩一张糊成星云的图。四条规矩：

1. **不要用 `scale()` 放大平面**（scale 连 Z 一起放大），尺寸按视口直接算；
2. 倾角和后推一起算账（现在 16° / 14° + `translateZ(-120)`），最坏情况 Z 位移要留出 perspective 的一半余量；
3. `copies` 要按「一列里有几张海报」算，不能只按视口高度除——前者算错会多铺好几倍的 DOM；
4. 墙的尺寸要封顶，不能只按视口比例算——超宽屏上斜墙的两端会自己伸到相机跟前。

**另一个坑**：`loading="lazy"` 在 3D 变换里浏览器判不准可见性，会一张都不加载。别加。

### 层级

页面根节点 `relative z-0`（不是 z-10），背景层 `fixed -z-10` 挂在它里面：

- 在内容列的 `bg-muted/50` 之上（负层直接挂在外面会被那层底色盖掉）；
- 在面板和文字之下；
- 顶栏是 `sticky z-20`，照常盖在上面（它本来就是毛玻璃，透出来正好）；
- **左右两边按 `[data-slot="sidebar-inset"]` 的实测位置收住**（`ResizeObserver` 跟着侧栏展开 / 收起变）。
  侧栏是 `fixed z-10`，但实测这层 fixed 背景还是会糊到导航上去，按几何收住最稳。
  **注意：2026-09-18 之前这一步从来没生效过**——量的 effect 只在挂载时跑一次，而头一次渲染 `enabled`
  还是 false、组件返回 null，`rootRef` 是空的，于是一直是 `left: 0; width: 100%`：墙铺到侧栏底下，
  中心和遮罩热点都往左偏了半个侧栏宽（1920 宽的屏上偏 128px）。现在等这一层真画出来（`shown`）再量。

strm 页的表格面板改成 `bg-card/60 + backdrop-blur-sm`，墙才透得出来。

## 四、什么时候不出现

| 条件 | 行为 | 为什么 |
|---|---|---|
| 有任务在跑 / 整理在执行 | 700ms 淡出到 0，停 rAF | 这个后台里「动」= 有任务在跑，不能被背景稀释 |
| 搜索模式 | 淡出 | 搜索结果和当前目录不是一回事 |

| 窄屏 < 768px | 不渲染，也不下载图（2026-09-18 前是 640px） | 和页面从卡片换成表格同一个断点（md）；卡片列表后面画墙只会拖慢它 |
| 页面切到后台 | 停 rAF | 别烧电 |
| `prefers-reduced-motion` | 显示但不动 | |

## 八、任务页：整个库（2026-09-18）

任务页没有「当前目录」，用户的说法是「用整个 strm 文件的数据」：把所有任务的本地目录当成一个库，抽一批作品海报。
墙还是那一面（`stream` 态），数据换了一个来源。第一版做完当天过了一轮评审（25 条，全部修了），下面记的是修完以后的样子。

### 接口

```
GET  /api/strm/posters/all
  → { posters: [{ taskId, path, source, url, title?, year?, tmdbId?, fallback? }] }   # 新的在前，最多 48 张

POST /api/strm/posters  { taskId, paths, offline? }
  → { posters: { [path]: … }, known: string[] }   # known：有线索的目录；offline 只用离线的几级
```

`local` 的 `url` 仍是相对任务根的，前端拿 `taskId` 走 `/api/strm/image`。`fallback` 见下面「大图换小图」。

### 找作品目录（`poster.ts` 的 `findWorks`）

宽度优先一层一层走，**每一层按修改时间新的先读**；所有库在同一层里一起排、共用一份额度（读目录 3000 次、stat 两万次）。
额度用完时丢掉的是旧的那头，也不会有哪个库被排在前面的那个饿死（第一版是按任务顺序各分一半，前一个任务目录再小也只能用一半）。

| 碰到的目录 | 怎么办 |
|---|---|
| 目录名带 id 标签 | 就是一部作品，**不用读它**（整理过的库几乎全是这种，走一遍只读分类目录那一两层） |
| 下面有季目录（用整理的 `seasonDirNumber`：`Season.01`、`Series 1`、`第一部`、`SP`、`番外` 都算） | 这是一部剧，**季目录不再读**；剧里别的子目录（版本、没认出来的季）也算它的 |
| 直接放着 strm / 作品 nfo / 目录级海报 | 这一层是一部作品，**但还要接着看子目录**：分类目录里散放一个 strm、或者放一张合集封面的，底下的作品不能跟着丢；花絮（`isExtrasDirName`）/ 艺术图目录不看 |
| 其余（分类目录） | 接着往下 |
| `@eaDir`、`#recycle`、`#snapshot`、`lost+found`… | 不进。只认这份名单：`#活着 (2020) [tmdbid=…]`（整理默认模板就能生成）、`@追更/` 这种分类照走 |
| 点开头的隐藏目录 | 不进（媒体服务器也不扫），名字带 id 标签的照算 |
| 符号链接 | 不跟（`isDirectory()` 对它是 false），不会跑出任务目录或绕成环 |

任务根自己带 id 标签（只同步了一部作品）就是那一部；解析时 id 标签取目录在磁盘上的名字，任务根也不例外。
几个任务共用一个本地目录的只走一遍；嵌在别的任务根里面的任务根交给它自己的任务（`nestedForeignRoots`，和 search 一样）。

### 共用本地目录的几个任务（`Library`）

算同一个库：④ 的整理记录把这几个任务的合起来查；库类型先验只在它们说法一致时才用，
不然谁排在任务表前面就听谁的，另一个任务的作品会按错的类型去查。

### 电影还是剧

id 标签不说类型，而 TMDB 的电影 id 和剧 id 是两套编号：猜错拿到的是另一部作品的海报，还会以对的键名写进共用的详情缓存。

- 猜：有季目录、或者 strm 名字带 `SxxEyy` 才算剧，其余当电影。第一版是「有子目录就当剧」，`@eaDir`、`.actors`、`Subs`、整理挪出来的 `extras` 都会让电影被当成剧；
- 核：目录名里括号括着的年份（`片名 (2010)`，取最后一个括号，`2024 (2021)` 不会取错）和详情的年份差一年以上就算对不上，换另一种类型问；缓存里的也一样核；
- nfo 给的 id 类型是确定的（tvshow.nfo / movie.nfo），只问那一种。

### 挑哪些、怎么挑

- **按作品目录的修改时间新的在前**：库不超过 48 部就是全部；大库给最近进来的——和任务页说的是一件事。
  `mtime` 只是近似（新集落在季目录里，剧目录自己的时间不变），当背景够用。
- 候选排好后每 48 个一轮解析，凑够 48 张或者看完 144 个就停；同一张图只留一次（外链按地址，本地图按库 + 路径）。

### 请求里不联网，缺的后台补

- `/api/strm/posters/all` **只用离线的几级**，不会被 TMDB 拖住。第一版是请求里现查（配额 12 次），TMDB 被墙时每次要等一个 15 秒超时，
  一轮能拖到三分钟，离线早就拿到的图也跟着等，前端 60 秒超时一到整面墙都是空的。
- 排得进墙、有 id、缓存里又没有的，交给后台（`warmLater`）：新的先问，一轮最多 12 次；问到了东西（有图，或者确认没有）就重算一遍墙换上，
  还缺就再来一轮，直到问完；一轮下来全是连不上就歇 30 分钟。
- **问过的都记住**：`TmdbClient` 把 404 也写进缓存，新加的 `peekTmdbCache` 分得清「没有这条」和「缓存着 null」。
  第一版把 404 和「有详情没海报」都当成没命中，每次重算都先把配额花在同一批上，更早的作品永远轮不到。同一个 id 在一轮里只问一次（4K / 1080p 两份不花两次）。
- 联网复用整理的 `TmdbClient`（读缓存、限速、拉取、写缓存都是它的），不再自己写一份。
- 结果在内存里留 5 分钟，**从算好的时候算**；过期了先给旧的、后台重算；键是任务（id、本地目录、库类型）加 TMDB 的语言和有没有 key。
- strm 页照旧当场联网（一个目录最多 24 个），但第一次连不上就停，不让剩下的每个都再等一回超时。

### 大图换小图、太大的当没有

- 任务页：本地图超过 512KB，离线有别的图（TMDB 的 w500 只有几十 KB）就换过去，本地那张的路径放进 `fallback`；都没有才用本地大图。
  刮削器存的多是原图，本机那张就 2.0MB；任务页是落地页、一面墙四十几张、常常隔着 Cloudflare 开。strm 页不换（单作品态铺满全屏，大图反而好）。
- 前端看到 `fallback`：先试这个外链的主机连不连得上（每个主机只试一次，8 秒为限），连不上就退回本地图——国内浏览器不一定连得上 TMDB 的图床，NAS 却可能走了代理。
- 比 `/api/strm/image` 的 16MB 上限还大的本地图**当没有**（两个页面都是）：第一版照用，浏览器拿到 413，别的来源也被它挡住了。

### 前端

- `hooks/use-all-posters.ts`：参数是任务表的指纹（id + 本地目录），变了才重拉——5 秒一次的状态轮询不会触发；请求失败隔 30 秒再要一次（头一回走库可能超时，后端照样算完存着）。
- 任务页根节点 `relative z-0`，表格面板 `bg-card/60 + backdrop-blur-sm`；**有任务在跑或在启动就淡出**，和第四节的规矩一致。
- `lib/poster-images.ts`（两个 hook 共用）：
  - 本地图**同时最多取 2 张**：它和接口是同一个源，HTTP/1.1 一个源只开 6 条连接，墙要是占满了，点「执行」都得排在几 MB 的图后面；
  - object URL 按最近使用淘汰，个数（80）和字节数（32MB）都封顶；**正在墙上的图钉住**，换下来才能淘汰——
    不然 revoke 之后窗口一缩放、列重排，新挂上去的 `<img>` 指着没了的 blob，就是一块空白。
- `useDirPosters`：**问接口不看屏幕宽窄，只有下载图看**——页头「N 个目录 · M 已识别」和「K 个没认出来」手机上也要。
  计数改成按 `known` 数（有没有线索，不是拿没拿到图），超过一屏（24 个）的子目录也分批离线数进去：第一版只数了前 24 个，目录一多「没认出来」就多报。
  卸载时停下（第一版没有清理函数，离开页面后还在接着下图）。
- `components/poster-backdrop.tsx`：阈值 768px（`useBackdropWide()` 导出给两个 hook 用，组件里也只留这一份）；
  量侧栏用 layout effect（先量再上屏，头一帧不会先铺满窗口再跳过去）；屏幕外的列（`IntersectionObserver`）不推，推一下它那层模糊就得重算。
- 路径的每一段不再 trim（`manage.ts` 的 `normalizeRel`）：目录名前后带空格是合法的，trim 掉 strm 管理的各个接口都找不到它。
